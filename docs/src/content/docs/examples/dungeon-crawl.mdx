## How it works

**The dungeon is vars.** The grid, the player and the log are data. `combat`
and `trap` hold the current room's rolls: a step sets them when the room
starts, and `leaveRoom` clears them however the room ends.

<Source file="games/dungeon-crawl/game.ts" region="types" />

**The run ends wherever the flow is.** The whole run is wrapped in
`outcomes` with two guards:

<Source file="games/dungeon-crawl/game.ts" region="run" />

- **`defeat`** holds at zero hp. Guards are checked after every transaction,
  so dying mid-fight or to a trap ends the run at once, however deep the flow
  is.
- **`victory`** holds when the dragon's hp is 0.
- **Outermost first.** The killing blow on the dragon also makes the fight's
  own `killed` guard hold. The run's guards are checked first, so it counts
  as victory, not just the end of a fight.
- Each `then` is a step that records the result. Then the `outcomes` node
  ends, and the session's "Play again" prompt waits.

See [Outcomes](/board-game-toolkit/concepts/outcomes/).

**Rooms are flow pieces in constants.** A node is a plain value, so `combat`,
`trap` and `treasureRoom` are built once as constants and used in the room
`branch`. There's nothing else to declare. See
[Reusing flow](/board-game-toolkit/guides/reusing-flow/).

<Source file="games/dungeon-crawl/game.ts" region="combat" />

**Fleeing raises an outcome.** The fight's `fled` outcome has no guard. The
`flee` action raises it by returning `{ exit: "fled" }` on a good roll, which
cancels the fight's loop and runs the outcome's `then`:

<Source file="games/dungeon-crawl/game.ts" region="flee" />

**A trap is a turn that stays open.** Each failed attempt to dismantle it
costs hp, and the turn waits for another. `dismantle` returns `"end"` on a
success, and `skip` returns it to walk away:

<Source file="games/dungeon-crawl/game.ts" region="trap" />

Moving between rooms is a `turn` too: `useItem` drinks a potion and keeps the
turn open, and `move` returns `"end"`.
