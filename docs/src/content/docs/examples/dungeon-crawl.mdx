## How it works

**Combat and traps are subflows.** The spec defines them once under
`subflows` and uses them from the room `branch` with `subflow("combat",
"combat")`. Their node ids get the use's id as a prefix, like
`combat.playerAttack`. See [`subflow`](../../reference/flow/subflow/).

**Guards decide the game wherever the flow is.** The `run` seq's exits turn a
dead player into `defeat` and a dead boss into `victory`, and its `on` map
runs a flow for each. Guards are checked outermost first, so killing the boss
in a fight wins the game rather than just ending the fight. See
[Outcomes and guards](../../concepts/outcomes/).

<Source file="games/dungeon-crawl/spec.ts" />

**Fleeing raises an outcome.** `tx.exit("fled")` ends the nearest node that
handles `fled`: the `fight` loop, whose `on.fled` logs the escape. The rest of
the handler still runs.
