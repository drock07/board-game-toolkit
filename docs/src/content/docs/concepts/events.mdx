Rules code never edits a state directly. `setup`, steps, action `execute`
and choices each receive a **transaction**, `tx`, and change state through it.
When the handler returns, the engine commits the transaction: the new state,
plus a list of **events** describing exactly what changed.

## Ops

Each op changes entities or zones and appends one event:

| Op                                    | Does                                                                                                    | Event       |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------- | ----------- |
| `tx.create(type, props, zone, opts?)` | Creates an entity. Goes to the **bottom** by default, so creation order reads top-down. Returns its id. | `created`   |
| `tx.move(ids, to, opts?)`             | Moves one entity, or several as a block in their current order. Goes to the **top** by default.         | `moved`     |
| `tx.moveTop(from, to, count?, opts?)` | Moves the top `count` (default 1). Throws if there are fewer. Returns the ids.                          | `moved`     |
| `tx.shuffle(zone)`                    | Shuffles a zone with the game's RNG.                                                                    | `shuffled`  |
| `tx.flip(id, faceUp)`                 | Sets an entity's `faceUp`.                                                                              | `flipped`   |
| `tx.destroy(id)`                      | Removes an entity.                                                                                      | `destroyed` |

`opts` for `create`, `move` and `moveTop` is `{ at?, faceUp? }`. `at` is
`"top"`, `"bottom"` or an index from the top. A move always resets `faceUp`:
pass it again to keep a card face down as it moves.

Using an op wrongly, such as an unknown zone or entity, throws an `OpError`.
That's a bug in the rules, not a bad move by a player.

## Vars and locals

`tx.vars` is a draft: mutate it like a normal object.

```ts
tx.vars.player.hp -= damage;
tx.vars.log.push("The dragon breathes fire");
```

All the changes to vars in one transaction become **one** `vars` event,
recorded as [immer](https://immerjs.github.io/immer/) patches. Locals work
the same way through `tx.local(nodeId)`, as one `locals` event per node.

## Everything else on tx

| Member                                | Does                                                                                                                           |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `tx.state`                            | The state, including this transaction's changes so far. Read-only.                                                             |
| `tx.scope`                            | Who and what this code is running for: `actor`, `player`, `item`, `iteration`, `event`. See [Prompts and inputs](../prompts/). |
| `tx.random`                           | The seeded RNG: `int`, `float`, `pick`, `shuffle`, `roll`. See [Determinism](../determinism/).                                 |
| `tx.emit(name, payload?, visibleTo?)` | A `custom` event for the UI, like "the enemy attacked for 6". Changes no state. `visibleTo` limits who sees it.                |
| `tx.exit(outcome)`                    | Ends the nearest node that handles `outcome`, once the transaction commits. See [Outcomes](../outcomes/).                      |
| `tx.end(result?)`                     | Finishes the game. `state.status` becomes `"finished"` and `state.result` holds `result`.                                      |

## Events

`apply` returns the events it produced, in order, each with a `seq` (its
position in the game's whole history) and `input` (which input caused it):

| Type        | Fields                                                            |
| ----------- | ----------------------------------------------------------------- |
| `created`   | `id`, `entity`, `at`                                              |
| `moved`     | `ids`, `from` (one zone per id), `to`, `at`, `faceUp?`            |
| `shuffled`  | `zone`, `order`                                                   |
| `flipped`   | `id`, `faceUp`                                                    |
| `destroyed` | `id`, `from`                                                      |
| `vars`      | `patches`                                                         |
| `locals`    | `node`, `patches`                                                 |
| `custom`    | `name`, `payload`, `visibleTo`                                    |
| `flow`      | `kind` (`enter`, `exit`, `prompt`, `resolve`), `node`, `outcome?` |
| `ended`     | `result`                                                          |

## Replaying events

Events are a complete record of what changed. `reduceEvents(state, events)`
applies them to an earlier state and rebuilds the later one's entities, zones,

## Events per player

Events can reveal hidden information: a `moved` event names the card that was
drawn. `viewEvents(game, before, events, viewer)` filters events for one
player. Ids of entities they can't see become opaque, `custom` events respect
`visibleTo`, and patches to hidden vars are dropped. See
[Views](../views/#events-per-player).
