Board Game Toolkit is a TypeScript library for building turn-based games:
card games, dice games, board games, and anything else where players take
turns, make choices and hide information from each other.

You describe a game in one place, with typed values:

- **The box**: entity types (a card, a die, a tile) and the zones they live in
  (a deck, a hand per player, a discard pile), with who may see each zone.
- **The rules**: the game's own state (its **vars**), the **actions** players
  can take, and a **flow**: a tree of nodes for rounds, turns and choices, and
  the order they happen in.

A pure, deterministic engine runs the game. A host, such as the React hook
`useGame`, puts it on screen.

## The core idea

The engine's main function is

```ts
apply(game, state, input) → { ok, state, events }
```

`state` is plain JSON, and the engine never changes it in place. An `input`
is a player taking an action: "bob plays card#7". The result is the new state
and the **events** that got there ("card#7 moved from bob's hand to the
table"). An illegal input isn't an error: it comes back as
`{ ok: false, reason }`.

Because the state is JSON and the random number generator lives inside it, a
game is fully determined by its seed and its inputs. That gives you saves,
replays and reproducible bug reports for free. And because each player gets a
**view** that leaves out what they can't see, the same model works for a
hot-seat game, a bot, or a server sending each client only their own hand.

## What's in the box

| Package                              | What it does                                                                                                                                    |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `@drock07/board-game-toolkit-engine` | Entities and zones, the flow, views and events, effects and abilities, the seeded RNG, saves, and `/testing`: bots, replays, fuzzing.           |
| `@drock07/board-game-toolkit-react`  | `useGame`, `useGameEvent` and `useGameEffect` for React, the framework-free `GameHost`, and `/devtools`: a live flow graph and fiber inspector. |

The engine has no dependencies and no UI. Use it on its own in Node, on a
server, or with another UI framework.

## Is it a good fit?

It's built for games where:

- **Turns and phases have structure.** Rounds of turns, a turn that stays open
  until you stand, everyone choosing at once, a reaction that interrupts the
  current player.
- **Information is hidden.** Hands, face-down cards, secret bids.
- **You want to test the rules.** Rules are pure functions of state, so
  they're easy to unit test, replay and fuzz.

It's not a rendering or physics engine: you bring the UI. Real-time games
don't fit the input-by-input model, and networking isn't included yet (see
[Running on a server](/board-game-toolkit/guides/server/) for the pattern).

:::note[Pre-1.0]
The engine was recently rewritten and is still in 0.x. Expect breaking changes
between minor versions until 1.0.
:::
