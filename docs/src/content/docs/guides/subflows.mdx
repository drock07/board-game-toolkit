When the same sequence appears in several places, such as combat in any room
or the same auction for each lot, write it once in `spec.subflows` and run it
with `subflow`. [Dungeon Crawl](/board-game-toolkit/examples/dungeon-crawl/) uses two: combat
and traps.

<Source file="games/dungeon-crawl/spec.ts" />

## Prefixed ids

`subflow("combat", "combat")` runs the `combat` subflow with every node id
prefixed by `combat.`: its `fight` node is `combat.fight`, its `playerAttack`
is `combat.playerAttack`. The same subflow used twice gets two sets of ids,
so prompts, flow events and locals stay unambiguous.

## Inputs and outputs

Subflows don't take parameters. They read what they need from state and
scope:

- **Locals**: the subflow's root node can build its own state from the
  current situation. Combat's `locals: "combatFromRoom"` copies the monster in
  the current room.
- **Scope**: inside an `each`, the subflow sees `scope.player` like any node.
- **Outcomes**: a subflow can end with an outcome its caller handles, like
  `fled`, or one handled further out.

## Checked at definition

`defineGame` reports a `subflow` naming a subflow that doesn't exist, a
subflow that's never used, and a subflow that uses itself.
