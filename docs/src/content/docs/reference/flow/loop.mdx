`loop` repeats: rounds until the deck runs out, lots until they're all
sold, or whole games forever. You write `loop(opts, body)`.

| Option  | Type             | What it is                                                                  |
| ------- | ---------------- | --------------------------------------------------------------------------- |
| `until` | `(s) => boolean` | Checked before every pass, the first included. The loop ends when it holds. |
| `body`  | `Node`           | The node to repeat. The builder's second argument.                          |

Three rounds of a bet, counted in the vars, then a prompt to play again. The
outer `loop({}, …)` plays forever.

## Behavior

- **`until` comes first.** It's checked before each pass, so a loop whose
  `until` already holds runs its body zero times.
- **No `until`, no end.** `loop({}, body)` repeats forever. That's right
  for the outermost loop of a game that's played again and again, as in
  every example. To end the game from inside, call `tx.end()`.
- **It must wait somewhere.** A loop whose body never waits for input
  spins; the engine throws `FlowStuckError` after 10,000 nodes.
- **Ending it early.** `until` isn't checked mid-pass. To stop in the middle
  of one, wrap the loop in
  [`outcomes`](/board-game-toolkit/reference/flow/outcomes/) with a guard,
  or raise an outcome from an action.

## What it shows

A running loop shows `{ pass }`: how many passes have started, this one
included, from 1. Read it with `loopNode.shown(view)`; when loops are
nested, you get the innermost. Use it for "Round 2" in a UI instead of
