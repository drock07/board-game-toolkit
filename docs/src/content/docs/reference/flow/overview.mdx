The flow is a tree of nodes. Each node is a plain object with a `kind` and an
`id`; the builders exported by the engine create them with less typing. See
[Flow](../../../concepts/flow/) for how the engine runs them.

| Kind       | Builder                                | Waits? | Page                     |
| ---------- | -------------------------------------- | ------ | ------------------------ |
| `seq`      | `seq(id, children, opts?)`             | No     | [seq](../seq/)           |
| `loop`     | `loop(id, body, opts?)`                | No     | [loop](../loop/)         |
| `each`     | `each(id, over, body, opts?)`          | No     | [each](../each/)         |
| `branch`   | `branch(id, cases, otherwise?, opts?)` | No     | [branch](../branch/)     |
| `step`     | `step(id, run, opts?)`                 | No     | [step](../step/)         |
| `decision` | `decision(id, opts, actions, common?)` | Yes    | [decision](../decision/) |
| `choose`   | `choose(id, opts)`                     | Yes    | [choose](../choose/)     |
| `pause`    | `pause(id, opts?)`                     | Yes    | [pause](../pause/)       |
| `parallel` | `parallel(id, children, opts)`         | No     | [parallel](../parallel/) |
| `exit`     | `exit(id, outcome, opts?)`             | No     | [exit](../exit/)         |
| `use`      | `subflow(id, name, opts?)`             | No     | [subflow](../subflow/)   |

## Options every node takes

| Option   | Type                      | Meaning                                                                                                          |
| -------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `id`     | `string`                  | Unique in the spec. Set by the builder's first argument.                                                         |
| `locals` | `string`                  | An `impl.locals` name. Its result becomes the node's locals each time the node is entered.                       |
| `exits`  | `{ [outcome]: Cond }`     | Guards. After every transaction, if a condition holds, the node ends with that outcome. Checked outermost first. |
| `on`     | `{ [outcome]: FlowNode }` | A flow to run when the node ends with that outcome.                                                              |

A **`Cond`** is either the name of an `impl.conditions` entry or an inline
[expression](../../spec/expressions/). See
[Outcomes and guards](../../../concepts/outcomes/) for `exits` and `on`.

## Builders and plain objects

Builders return exactly the object you'd write by hand, and keep every string
as a literal type so `defineGame` can check names:

```ts
decision("turn", { actor: "current" }, { play: {}, pass: {} });
// { kind: "decision", id: "turn", actor: "current", actions: { play: {}, pass: {} } }
```

Specs loaded from JSON with [`fromJSON`](../../spec/json/) use the plain form.

## Custom node kinds

`defineGame(def, { kinds })` accepts custom node kinds, through the exported
`NodeKind` interface. This extension point is **experimental**: custom kinds
can't have children yet, and a custom node needs a type cast in the spec. Use
the built-in kinds for now.
